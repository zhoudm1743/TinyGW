# Q3761-1376 DLT645透明转发插件使用说明

## 概述

本插件实现了Q/GDW 1376.1协议与DLT645协议的透明转发功能，主要用于4G电表的远程通信和控制。

## 功能特性

### 支持的命令

1. **dev_consumption** - 读取正向总有功电能
2. **OpenValve** - 跳闸操作
3. **CloseValve** - 合闸操作
4. **login** - 登录命令
5. **heartbeat** - 心跳命令
6. **logout** - 退出登录
7. **transparent** - 自定义透明转发
8. **version** - 读取终端版本
9. **module_version** - 读取模块版本

## 设备配置说明

### 地址配置

4G电表需要配置两个地址，支持以下几种配置方式：

#### 方式1: 使用分隔符格式（推荐）
- **Device.Address** = "053040961|202505300001" (通讯地址|电表地址)
- 采用 `|` 分隔符，前面是通讯地址(用于3761通信)，后面是电表地址(用于DLT645通信)

#### 方式2: 单一地址 + commandParam
- **Device.Address** = "202505300001" (电表地址)
- 通过commandParam传入通讯地址

#### 方式3: 完全通过commandParam指定
- **Device.Address** = 任意值
- 通过commandParam明确指定两个地址

### 参数传递

- **sAddr参数**: 自动传入Device.Address的值
- **commandParam**: JSON字符串，可选覆盖地址配置

```json
{
  "commAddr": "053040961",      // 通讯地址(可选，覆盖sAddr中的通讯地址)
  "meterAddr": "202505300001",  // 电表地址(可选，覆盖sAddr中的电表地址)
  "password": "123456"          // 操作密码(拉合闸时需要)
}
```

## 使用示例

### 1. 使用分隔符格式（推荐）

设备配置：`Device.Address = "053040961|202505300001"`

```lua
-- 读取正向总有功电能
local result = DeviceCustomCmd(sAddr, "dev_consumption", "", 0)

-- 跳闸操作
local cmdParam = json.jsonencode({
    password = "123456"  -- 只需传入操作密码
})
local result = DeviceCustomCmd(sAddr, "OpenValve", cmdParam, 0)

-- 合闸操作
local cmdParam = json.jsonencode({
    password = "123456"
})
local result = DeviceCustomCmd(sAddr, "CloseValve", cmdParam, 0)
```

### 2. 使用commandParam覆盖地址

```lua
-- 读取正向总有功电能
local cmdParam = json.jsonencode({
    commAddr = "053040961",
    meterAddr = "202505300001"
})
local result = DeviceCustomCmd(sAddr, "dev_consumption", cmdParam, 0)

-- 跳闸操作
local cmdParam = json.jsonencode({
    commAddr = "053040961",
    meterAddr = "202505300001",
    password = "123456"
})
local result = DeviceCustomCmd(sAddr, "OpenValve", cmdParam, 0)
```

## 协议处理流程

### 命令生成流程

1. **接收调用** - Go程序调用`DeviceCustomCmd`
2. **参数解析** - 解析JSON格式的`commandParam`
3. **DLT645命令生成** - 根据命令类型生成对应的DLT645帧
4. **透明转发封装** - 将DLT645帧封装到3761透明转发帧中
5. **返回命令** - 返回完整的3761帧供4G模块发送

### 响应解析流程

1. **帧接收** - 接收3761协议响应帧
2. **帧校验** - 验证3761帧的完整性和校验和
3. **透明转发解析** - 提取透明转发数据内容
4. **DLT645解析** - 解析嵌套的DLT645响应帧
5. **数据提取** - 提取业务数据并格式化输出

## 数据格式说明

### DLT645数据标识

- **00 00 01 00** - 当前正向有功总电能
- **控制命令** - 通过控制码0x1A(跳闸)和0x1B(合闸)实现

### 响应数据解析

插件能够解析以下DLT645响应：

- **0x91** - 读数据成功响应
- **0x9C** - 写数据成功响应  
- **0xD1** - 读数据异常响应
- **0xDC** - 写数据异常响应

## 错误处理

### 常见错误码

- **error_XX** - DLT645协议错误，XX为具体错误码
- **帧长度不足** - 接收数据长度小于最小帧长
- **校验和错误** - 数据传输过程中出现错误
- **地址不匹配** - 响应帧地址与期望地址不符

### 调试建议

1. 检查设备地址配置是否正确
2. 验证通信模块连接状态
3. 确认操作密码设置
4. 查看日志输出的错误信息

## 设备模型配置示例

### 在系统中配置4G电表设备

```json
{
  "name": "4G电表001", 
  "address": "053040961|202505300001",
  "type": {
    "name": "Q3761-1376",
    "driver": "Q3761-1376.lua"
  },
  "collector": {
    "name": "4G采集器001",
    "type": "FourGPRS",
    "fourGPRS": {
      "name": "053040961"
    }
  }
}
```

### 关键配置说明

1. **device.Address**: 使用分隔符格式 "通讯地址|电表地址"
2. **device.Type.Driver**: 指定使用 "Q3761-1376.lua" 
3. **device.Collector.FourGPRS.Name**: 通讯号码，应与Address中的通讯地址一致

## 注意事项

1. 确保4G模块支持透明转发功能
2. 验证电表支持DLT645协议
3. 操作密码错误可能导致拉合闸失败
4. 通信超时时间建议设置为30秒以上
5. 使用分隔符格式时，确保通讯地址和电表地址格式正确
6. 普通采集任务和RPC命令都支持地址解析功能
